# Hole Punch (formerly Portal 2D): notes for Claude

Pixel-art portal puzzler that runs in the browser: plain JavaScript modules on a 640x360 canvas, no bundler, no
dependencies. Live at https://portal.crooli.com (also xandertaylorx.github.io/portal-2d-game/) (GitHub Pages). See README.md for the architecture.

The original C# + Raylib desktop version is frozen in `OLD-DESKTOP/` (see its README). Don't add features there.

## Layout

- `index.html` (page shell + fullscreen button), `favicon.png`, `src/` (game), `data/` (levels as JSON), `tests/`, `tools/`.
- `src/world.js` physics/portals/lasers (port of the C# `World.cs`), `render.js` scene + CPU portal lenses, `app.js` screens/HUD,
  `editor.js` map builder, `library.js` My Maps/featured, `art.js` sprites/tiles/character customiser, `maps.js` saves + share codes.
- Dev server: `python3 -m http.server 8000`. `?level=N` / `?screen=select|options|controls|character|mymaps|editor` deep-link.

## "commit push" means test, bump, commit, push (Pages deploys itself)

1. `node tests/replay.mjs` must print "all N replays match" **and** "all N web-built levels have a working solution" (needs `test/traces.json`,
   generated by the C# exporter, gitignored; if missing, run the export below). `node tests/boss.mjs`, `node tests/progress.mjs` and `node tests/ghost.mjs` must also pass.
2. Bump `VERSION` in `src/app.js` and the badge in README.md, add a `## [x.y.z] - date` section to CHANGELOG.md
   (patch = fixes, minor = features). Changelog is written for players.
3. Commit and push to `main`. `.github/workflows/pages.yml` deploys `index.html`, `favicon.png`, `src/`, `data/`.
4. There are NO more GitHub releases or desktop builds. Old desktop installs check `releases/latest`, so don't publish a
   release without the `Portal2D-<rid>.zip` assets. (`OLD-DESKTOP/scripts/` is retired.)

## Levels

- Chambers and Random Test pools are NOT authored in JS. They come from the C# game: `dotnet run --project OLD-DESKTOP/src/Portal2D -c Release -- --export-web data`
  writes `data/levels.json`, `data/random.json` and `test/traces.json`. Chambers 1-21 in `Game/Levels.cs`, 22-41 in `Game/Chambers.cs`,
  42-53 composed from `Procgen` rooms (see OLD-DESKTOP). Best times are saved by chamber **name**, so renaming resets them.
- If physics changes, change `src/world.js` and re-run the export, then `node tests/replay.mjs`, so the C# solutions still prove every chamber solvable.

## Every chamber needs a solution (rule)

Any chamber or random test that is not exported from the C# game MUST ship with a verified `solution` (the same per-frame input string the C#
traces use), and `node tests/replay.mjs` fails if one is missing or does not win. Solutions power WATCH SOLUTION, par times and the tests.
Fast ways to get one:

1. **Bot (best).** `tools/bot.mjs` is a scripted player: `walkTo`, `jump`, `shoot('blue', x, y)`, `use`, `track`, `finish`. It plays the real physics, so
   macros react to where things actually are, and `bot.inputs()` is the solution. `tools/stages.mjs` already has solved building blocks (hop, pit,
   vault, button, lift, gel, turret, nest, gauntlet, hall): add a stage there (it draws itself AND solves itself) and list it in
   `tools/build-levels.mjs`, then run `node tools/build-levels.mjs`. That rewrites `data/bonus.json` (the 20 web chambers appended after the 100
   exported ones) and `data/random2.json` (15 difficulty tiers mixed into the random tests), every level replay-verified.
2. **Record by hand.** In any campaign or random chamber press **F8** (restarts the chamber and records at exact 60 fps), play it through, and on
   completion the solution JSON is copied to the clipboard (also `window.lastSolution`). Paste it into the level's `solution` field.
3. Exported C# chambers get theirs from `test/traces.json`: run `node tools/make-solutions.mjs` after re-exporting (writes `data/solutions.json`
   and `data/pars.json`).

## Progress file

`SaveData.toFile()` / `mergeFile()` (src/maps.js) back the Options EXPORT/IMPORT PROGRESS buttons. A new save field is picked up by export automatically;
if it needs a special merge rule (best-of, max) add it in `mergeFile`. `node tests/progress.mjs` covers it.

## Boss fight

`src/boss.js`: `bossArena()` is the fixed 32x18 arena (two ledges over a goo pit, one ceiling panel above the mech), `Boss` runs COLOSSUS: mortar shells that
arc under gravity and pass through portals, a hatch that is open for a few seconds after each volley, three phases (shockwaves, then purge and twin shells),
hearts, checkpoints per phase. A reflected shell leaves a portal straight along its normal so the geometry is forgiving. The blue portal burns out 0.8 s after
it catches a shell so it can't trap you. `tests/boss.mjs` plays it with a bot that only uses portals and must win every run: re-run it after changing any
timing or geometry, because it is the proof the fight is beatable. Fight records are `save.bossWins` / `save.bossBest` (the old duel's `fight*` fields are unused).
The world hooks `World.extra` / `fightHooks` from the retired duel are still there but unused.

## Playground

`src/playground.js` generates the endless world: `generateChunk(index, seed)` is a pure function (80-column chunks, 96 rows) built from noise: `biomeAt`,
`naturalSurface`, caves, sinkholes with a lift and a relic chamber, lava below row 88, and structures (park, lab, tower, fling, bounce, speed) placed in
two slots per chunk, never within 10 columns of a chunk edge so seams stay smooth. `PlaygroundWorld` streams cubes and lifts per chunk and tracks relics and
fling distance. `src/playground-art.js` draws it. `node tests/playground.mjs` must pass, and it plays the launch tower course, so any change to that
structure's geometry has to keep it solvable (portal high on the tower wall, portal on the ground, step off, land on the mesa). `tests/playground.html`
is a browser check of the rendering.

## Main menu

The menu screens draw `App.drawBackdrop()` (a static blueprint scene), not the menu world. Do not put live game footage behind menus.

## Ghosts, par times and new tiles

- `data/solutions.json` + `data/pars.json` come from the C# reference solutions: after re-exporting levels run `node tools/make-solutions.mjs`
  (needs `test/traces.json`). Pause menu WATCH SOLUTION replays a solution through its own World (`src/ghost.js`); par = 1.5x the reference run
  (gold), 1.5x par silver. Best-run ghosts are recorded samples saved in `save.ghosts` by chamber name.
- Tiles added in the web version only (not in any exported chamber, editor/custom maps only): `S` sentry turret, `B` lift beam (up), `D` push beam (down).
  Keep new mechanics additive so the C# replays still match.
- Lighting: `render.js` builds a half-res light map from ray-cast lights (`collectLights`/`applyLighting`), multiplies and doubles it over the
  scene, then draws emissive things (lasers, portals, goo, fizzlers, holograms, shafts) on top. `PP.Ambient` sets how dark it is.

## Character customiser

- `src/art.js`: `COLORS`, `HATS` (rects relative to the body's top row), `FACE_NAMES`, `OUTFIT_NAMES`, `buildPlayerSheet(look)`. Frames are 16x20
  (4 spare rows on top for hats). Look is saved in `save.look` and applied with `Sprites.setLook`. Preview all combos by rendering
  `buildPlayerSheet` to a PNG in Node (Pix has no DOM dependency).

## Map builder and featured maps

- Maps live in localStorage; share codes (`P2D1:` + base64 gzip JSON, PascalCase fields) are byte-compatible with the old desktop game.
  The web SHARE button copies `<page>#P2D1:...`, which the game imports on load.
- `featured/maps.json` on `main` is what FEATURED MAPS downloads (raw.githubusercontent.com). Keep it at that path: old desktop builds read it too.
  Entries: `{ "name", "author", "note", "code" }`.

## HUD fade

- `Gfx.opacity` multiplies every draw; `App.hudAlpha(key, rect)` returns 0.2..1 depending on whether the cursor is over `rect`.
  Wrap any new HUD element drawn over the playfield in it.
